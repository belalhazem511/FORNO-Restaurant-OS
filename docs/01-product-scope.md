# نطاق FORNO Restaurant OS

## الهدف

مصدر بيانات واحد يربط الكاشير، المطبخ، المخزون، الحسابات الإدارية، والمنيو العامة. أي طلب مكتمل يجب أن ينعكس تلقائيًا على المبيعات، استهلاك المكونات، وحالة الاحتياج للشراء.

## مستخدمو النظام

| الدور | أهم ما يحتاجه |
|---|---|
| الكاشير | فتح وردية، إنشاء طلب، إضافات وملاحظات، دفع، طباعة، إلغاء بصلاحية |
| المطبخ | طلبات مرتبة حسب الوقت والمحطة، بدء التحضير، جاهز، تأخير |
| مدير الفرع | المخزون، الجرد، المشتريات، الهالك، الورديات، أداء اليوم |
| المالك | المبيعات، تكلفة البضاعة، الربح، المصروفات، المقارنات والتنبيهات |
| العميل | قصة المطعم، المنيو والأسعار والتوفر، الفروع ووسائل التواصل |

## النسخة الأولى MVP

### 1. نقطة البيع

- Dine-in وTakeaway وDelivery.
- الطاولات الأربع وحالة كل طاولة.
- أحجام وإضافات الأصناف، مثال: حجم البيتزا ونوع الجبن.
- ملاحظات المطبخ وتقسيم/دمج الطلب عند الحاجة.
- نقدي، بطاقة، وإنستاباي مع إمكانية تقسيم الدفع.
- وردية كاشير: فتح، حركات نقدية، وإغلاق مع فرق الخزنة.
- طباعة إيصال وKitchen Order Ticket.

### 2. المطبخ KDS

- توجيه الأصناف إلى محطة Pizza أوDoner أوCafe.
- حالات New → Preparing → Ready → Served/Collected.
- مؤقت للطلب وتنبيه عند تجاوز زمن التحضير.

### 3. المخزون والوصفات

- مكونات بوحدات قياس قابلة للتحويل: كجم/جم، لتر/مل، قطعة.
- موردون، أوامر شراء، واستلام جزئي أو كامل.
- وصفة لكل صنف وحجم، مع خصم تلقائي عند إكمال الطلب.
- جرد، تسوية، هالك، مرتجع مورد، وتحويل بين المواقع.
- حد إعادة الطلب واقتراح احتياج محسوب من الاستهلاك والمخزون.

### 4. الإدارة والربحية

- المبيعات حسب اليوم، الساعة، الصنف، التصنيف، وطريقة الدفع.
- إجمالي الربح = صافي المبيعات − تكلفة المكونات المباعة.
- صافي تشغيلي مبسّط = إجمالي الربح − المصروفات المسجلة.
- أفضل/أضعف الأصناف، الهالك، والفروقات بين المخزون النظري والفعلي.
- سجل تدقيق للإلغاء، الخصم، تعديل المخزون، وإعادة الطباعة.

### 5. الموقع العام

- صفحة قصة FORNO وصور المكان.
- منيو عربية/إنجليزية من نفس قاعدة الأصناف والأسعار.
- إخفاء الصنف أو إظهار “غير متوفر” من الداشبورد.
- بيانات التواصل، الموقع، وساعات العمل.

## خارج النسخة الأولى

- Marketplace كامل أو تطبيق عميل Native.
- Loyalty متقدم ومحفظة نقاط.
- محاسبة قيود يومية كاملة بديلة لبرنامج محاسبة متخصص.
- تعدد فروع متقدم؛ سنصمم البيانات لتدعمه لكن نطلق بفرع واحد.
- ربط مباشر بمنصات التوصيل قبل ثبات دورة الطلب الأساسية.

## قواعد مالية لا نتنازل عنها

- تخزين النقود كأعداد صحيحة بأصغر وحدة نقدية، وليس floating point.
- عدم حذف العمليات المالية المكتملة؛ يتم العكس أو الإلغاء بسجل تدقيق.
- تثبيت سعر البيع وتكلفة الوصفة داخل الطلب وقت البيع لحماية التقارير التاريخية.
- الفصل بين مخزون المنيو “متوفر للبيع” ومخزون المكونات الفعلي.
